# Governance

SRay is maintained by [Azizbek Asadov](https://github.com/azizbek-asadovnzzemu). The maintainer triages issues, coordinates releases, moderates community spaces and records scope decisions publicly.

Technical proposals belong in issues. Decisions should state the user problem, alternatives, trade-offs and verification. Deaf and hard-of-hearing community feedback and ASL evaluation are required for communication-quality claims. Maintainer approval cannot substitute for linguistic validation.

At least one independent reviewer must approve a PR. Until an independent reviewer is available, implementation PRs remain open; the maintainer does not waive review by self-approval. Code ownership requests review but does not by itself provide independence.

Release priorities follow the PRD and milestones. Later-language issues are exploratory until coverage and evaluation evidence exists. Public source availability is not a claim of production readiness.

The initial documentation commit bootstraps main and develop. Subsequent changes follow the contribution workflow. Changes to governance or licensing require a public proposal and review; contributors retain their copyright.
